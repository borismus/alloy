# Backlog

Tasks for the autonomous backlog runner (`scripts/backlog-runner.sh`).
Each `- [ ]` is one self-contained task. The runner picks the first open one,
works it on an `auto/<slug>` branch, verifies, and opens a PR for review.

Keep tasks small and unambiguous — one PR's worth of work each. Completed work
and the mobile-reliability checklist are archived in
[`docs/backlog-archive.md`](docs/backlog-archive.md).

<!-- Tier 1: observed correctness failures and their prerequisites. -->
- [ ] Let the model continue reading past a truncated tool result. `read_file` caps output at 64 KB (`MAX_READ_BYTES`) and appends `[truncated: file is N bytes; showing the first 64 KB]`, but takes no offset, so the remainder of a large note or conversation YAML is simply unreachable — the model either answers from the head or re-reads the same head. `web_fetch` already solves this with `start_index`/`max_chars` plus a continuation marker, and `list_directory`/`search_directory` already page with limit/offset; make `read_file` consistent with them. The per-turn budget now suppresses an exact repeat, so a model that reacts to truncation by re-reading gets a duplicate reference instead of the missing tail, which makes the gap more visible rather than less. Keep the default first page identical to today's behavior so existing prompts are unaffected, page by character offset (not bytes) so multi-byte content can't split, and state the remaining length in the marker. Cover truncation, continuation, an offset past the end, and multi-byte boundaries; extend the same treatment to the MCP schema so Claude/Codex see the new parameters.
- [ ] Give task execution its own turn limits, separate from interactive chat. Scheduled runs go through `tasks::executor::run` and inherit interactive defaults such as `MAX_ITERATIONS = 10`, `MAX_WEB_SEARCHES = 3`, three subagents, and 8192 output tokens, even though cron runs deliberately favor accuracy over speed. The old 180-second total request deadline has already been replaced by 30-second connect and 180-second idle-read deadlines, so do not reintroduce a total generation timeout. Introduce an internal execution policy on `StartParams` that HTTP callers cannot opt into. Key it on **task mode, not whether the model is local**: locality is a trust signal, and cloud cron runs deserve the same task policy. Because **Run now** shares the executor path, manual and automatic runs must resolve to the same policy. Ship bounded generous defaults with global and per-task overrides, keep interactive chat unchanged, preserve task-only pre-response retries, hold the scheduler lock for the entire run, and keep cancellation clean. Cover policy isolation, cron/Run-now parity, configuration, and a slow multi-step task exceeding the old limits and persisting/emailing one final result.

<!-- Tier 2: failure salvage, data protection, and diagnosability. -->
- [ ] Protect `memory.md` from a destructive model rewrite. It is the one file injected into every system prompt, so damage there silently degrades every future turn in every conversation, and it is hand-curated (41 lines: 5 headings, 22 bullets) so it cannot be reconstructed from anything. `skills/save-memory/SKILL.md` instructs the model to `write_file` the **complete** updated content, and `execute_write` in [alloy-server/src/tools/files.rs](alloy-server/src/tools/files.rs) is a plain `fs::write` truncating overwrite — so a model that summarizes carelessly or truncates mid-generation replaces curated memory with less than it had. There is no git history in the vault, no backup file, and no diff shown. This is specifically about `memory.md`; ordinary `notes/` writes should remain unchanged. Replace it atomically, retain a small timestamped rolling backup set of non-identical prior versions outside prompt/search scope, and reject or quarantine suspicious empty/sharp-shrink writes unless the caller proves it read the current revision. Never expose backup contents in logs, document manual restore, and cover normal updates, stale revisions, suspicious shrink, interrupted writes, and backup rotation.
- [ ] Preserve bounded provider-supplied reasoning when a conversation turn fails. `SessionInner.full_thinking` already retains up to 128 KiB for live replay, but `mark_error()` clears it and `AssistantWrite` has no reasoning field, so a long failed run can leave an empty assistant record even when the provider streamed useful working notes. On the existing atomic failed assistant record only, persist that buffer in a clearly named optional field, render it as collapsed **Incomplete model reasoning**, and include a labeled section in the generated Markdown preview for posterity. Never invent reasoning for providers that do not supply it, persist it for successful turns or metadata logs, or feed it back into later model context. Preserve the existing bound and truncation marker. Treat this as diagnostic salvage, not as a final answer or a substitute for preventing failure. Cover failures before and after visible content, reconnect/reload, Markdown generation, absent reasoning, truncation, and secret-canary exclusion from logs.
- [ ] Log enough to explain a turn after the fact, and keep the logs. `init_logging` in [src-tauri/src/lib.rs](src-tauri/src/lib.rs) writes only to stderr, which is discarded when the app is launched from Finder — so a production failure leaves no diagnostic anywhere. Add a rotating log file in the platform log directory (`~/Library/Logs/Alloy` on macOS) alongside stderr, keeping the `ALLOY_LOG` override and a small retention cap, and share one initializer between the Tauri shell and `alloy-serve`. Then log what actually explains a turn: model and provider, message count, each tool-loop iteration's stop reason, tool-call count and names, whether the forced wrap-up fired and why, final content length, token usage, and duration. **Log metadata only — never message text, tool results, prompts, note contents, or credentials**, since these files sit unencrypted next to a private vault; where output shape matters, log a classification (for example “final content looks like unparsed tool-call markup”) rather than the text. A recent investigation could not determine whether malformed output came from a loop round or the wrap-up because neither is logged at any level.
- [ ] Make it obvious which build is running. Debugging twice reached the wrong conclusion because a stale Tauri dev binary kept serving old code: `npm run tauri dev` only rebuilds Rust at process start, and the dev log showed repeated `0.0.0.0:3041 is already in use` from competing Alloy instances whose output went to different places. Surface the running build — version, git commit, and build timestamp — in Settings and in a startup log line, sourced at compile time so it cannot drift. In dev, make a port conflict impossible to miss rather than falling back silently to another port while an older instance keeps serving the UI. Cover the version/commit plumbing with a test and check the conflict path in both Tauri and standalone modes.

<!-- Tier 3: contained UX and feature work. -->
- [ ] Wrap long unbreakable titles in the sidebar timeline. `.item-preview` in [src/components/Sidebar.css](src/components/Sidebar.css) sets no `overflow-wrap`, so a conversation titled with a bare URL (the fallback title is the first message) runs past the card's right edge and is visually clipped, while the remainder wraps to the next line — e.g. `https://www.collisiondetector.com/front` + `the`. The sibling `.item-search-snippet` already handles this with `overflow-wrap: anywhere`. Apply equivalent breaking to the title while keeping its existing two-line clamp, ellipsis, and the right padding that leaves room for the actions button. Check a long URL, a long unspaced word, and ordinary prose titles at both desktop and mobile sidebar widths.
- [ ] Add native PDF attachments to conversations. Generalize the current image-only `Attachment`, pending-composer, queue, vault-storage, and server message types to support `document` attachments while preserving every existing image path. Accept `application/pdf` from the file picker and drag-and-drop, store the original PDF under `conversations/attachments`, and render an accessible filename chip before and after sending. Add a provider/model `supportsDocuments` capability and send PDFs only through verified native document protocols (initially Claude subscription and OpenRouter); unsupported providers such as Codex app-server and oMLX must block the attachment with a clear explanation rather than silently dropping it or uploading it elsewhere. Respect each upstream size/page limit, keep vault paths private, and never fall back from a local provider to cloud. Cover Tauri and browser/server modes with unit tests for capability gating and wire shapes plus a smoke test using a real small PDF.
- [ ] Implement manual conversation compaction end to end, then restore the **Compact now** action in the context-usage popover. Add an authenticated backend route that compacts the selected persisted conversation using the existing server-owned compaction/model-selection machinery, writes the compacted boundary atomically without dropping attachments, tool history, newer turns, or concurrent optimistic user messages, and returns the updated conversation. Reuse the automatic-compaction format and provider-native one-shot model behavior rather than creating a second summary schema. The client action must show progress, reload the resulting conversation, preserve scroll sensibly, and surface failures without leaving a false compacted state. Keep automatic compaction unchanged and cover Tauri and browser/server modes with Rust route/persistence tests and a frontend interaction test. Do not expose a placeholder button before the backend path works.

## Deferred (not scheduled — no `- [ ]`, so the runner skips it)

- **Optimize per-token Markdown rendering only after a measured regression.** `MarkdownContent` is currently re-parsed as streaming state changes, but the previously measured 284 ms typing stall came from the now-windowed 1,302-row sidebar, and current conversation responsiveness is acceptable. Do not optimize based on the old measurement. If streaming in a long Markdown/math/code conversation becomes observably slow, first profile render/parse counts, then isolate the active streaming row and memoize completed message bodies while preserving tool pills, wiki links, math, syntax highlighting, find-in-conversation, and auto-scroll. Do not virtualize the message list because browser find relies on its DOM.
